# Physical registration replay and guarded pairwise interface

This directory is an audit and fail-closed engineering patch. It does not
establish that the recorded system estimated correct online relative poses.
The ten physical bags contain `/merged_map` rasters, but no transform,
candidate, gate decision, or commit topic. Consequently, every transform in
the event table is an offline reconstruction.

## Audit outcome

The canonical run covers the ten `sense1-1` through `sense5-2` bags.

| Quantity | Count |
|---|---:|
| Replayed cached-map callbacks | 1,644 |
| Recorded `/merged_map` publications | 1,485 |
| Publications exactly reproduced as ordered rasters | 1,325 (89.23%) |
| Exactly reproduced publications failing SE(2) structure | 1,263 / 1,325 |
| Exactly reproduced publications passing structure and 0.25 m / 5 deg | 0 / 1,325 |
| Exactly reproduced publications passing structure and 0.50 m / 10 deg | 22 / 1,325 |

The historical matcher used `estimateAffinePartial2D` and committed its result
without a scale gate. Exact raster reproduction supports the link between the
historical implementation and many recorded publications, but raster equality
does not prove that a particular matrix was recorded online. Repeated rasters
can also be generated by more than one cached-map state.

A second, counterfactual path estimates a proper unit-scale SE(2) transform
directly from one-to-one feature correspondences using deterministic two-point
RANSAC and Kabsch refinement. Thresholds were developed on `sense1-1`, frozen,
and then evaluated on the other nine bags. After local evidence checks and
three independent temporal confirmations, it produced eight counterfactual
commits. None met 0.25 m / 5 deg. Two met 0.50 m / 10 deg and six did not.
Therefore this path is not validated for state mutation.

The operational recommendation is fail-closed. `PairwiseRegistrationManager`
defaults to `commit_enabled=False`; it may compute candidates and diagnostics,
but it does not call the supplied committer. Enabling commit is an explicit,
keyword-only experimental override and is not justified by these bags.

## Provenance boundary

The exact legacy replay requires the historical matcher checkout supplied
separately at commit:

```text
0e93b819a9610ed2924858d16bf032729d21fb67
```

The replay subscribes conceptually to the historical pair
`/robot_0/predicted_map` and `/robot_1/predicted_map`, in bag record order. The
historical node itself hard-wired that pair. The new manager accepts arbitrary
configured robot IDs and keeps consensus state isolated per unordered pair.
Only two-robot physical bags are available here. The three-robot behavior is
covered by synthetic unit tests, not by a three- or five-robot physical claim.

The UAV JSON alignment is independent of map matching and is used only after
candidate generation and gating. The original calibration script interleaves
the two robots' residuals before splitting the two displayed RMS labels. The
joint fitted transform is retained, but those two labels must not be treated as
robot-specific uncertainty estimates. No stored bootstrap interval is
available.

## Run the canonical replay

From the `MSO_public` repository root:

```powershell
py -3 -m pip install -r registration_replay\requirements-lock.txt
py -3 registration_replay\replay_physical_bags.py
```

Defaults assume the repository is located beside `Exp`, `corl_2026`, and the
separate historical matcher checkout. Paths can be changed with `--workspace`,
`--bag-root`, `--reference-root`, `--matcher-root`, and `--output`.

The run records Python, NumPy, OpenCV, source hashes, bag hashes, frozen
thresholds, and limitations in `results/manifest.json`. OpenCV/RANSAC version
differences and callback scheduling can prevent exact reproduction of some
historical outputs. Unreproduced publications remain unevaluable.

## Canonical outputs

- `results/registration_attempts.csv` contains one row per replayed cached-map
  callback. It includes the legacy affine, rigid candidate, gate reasons,
  metric pose, reference errors, raster-verification flag, independent
  consensus support, and counterfactual gate decision.
- `results/recorded_merged_outputs.csv` accounts for every recorded publication
  and links exact matches to replay attempts.
- `results/bag_summary.csv` reports per-bag and all-bag counts.
- `results/bag_topic_inventory.csv` records bag topic/type/message counts.
- `results/uav_reference_summary.csv` records the reference parameters and the
  RMS-label warning.
- `results/manifest.json` records provenance, versions, thresholds, input bag
  hashes, and interpretation limits.
- `results/SHA256SUMS` fixes the canonical output bytes.

An `attempt` is a replayed predicted-map callback after both map caches exist.
It is not an independently labelled communication encounter. A rejected bad
candidate and a rejected good candidate are evaluation proxies, because the
bags do not contain encounter ground truth. The `later_good_candidate` fields
mean only that a later replay candidate satisfies the selected diagnostic
threshold. They do not demonstrate rollback, state restoration, or repair
after a bad fusion.

## Candidate, gate, consensus, commit

The write barrier is explicit:

```text
feature correspondences
    -> constrained SE(2) candidate
    -> structure, inlier, residual, occupancy, and spatial-spread gate
    -> per-pair temporal consensus
    -> committer only when explicitly enabled
```

Temporal confirmation is reset by a local rejection. A confirmation counts
only when both cached map revisions changed, at least 0.5 s elapsed, the gap is
at most 5 s, and translation/yaw remain within 0.5 m / 5 deg. Pair states do not
share evidence.

## Tests

```powershell
py -3 -m unittest discover -s registration_replay\tests -v
```

The tests cover unit-scale estimation with outliers, rejection of scale,
reflection, and shear, fail-closed default behavior, explicit commit after
three independent confirmations, reset after rejection, pair isolation, and a
three-ID queue. These are unit and offline tests only.
